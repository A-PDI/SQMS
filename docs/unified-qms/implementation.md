# Implementation and integrity rules

## Platform and boundaries

The target is the existing NestJS/Next.js/Prisma modular monolith, one MySQL schema, the existing private object store, Redis worker, ClamAV and shared audit/workflow/task/notification services. No legacy Express server, SQLite adapter, startup migrations, JWT client or second operational backend is started. Reusable calculations and PDF content live in `packages/legacy-domain`; its provenance records the inspected source. JavaScript section editors are wrapped by typed SQMS pages, authenticated by SQMS cookies.

Supplier, InternalPart, SupplierPart, SupplierProduct, site, configuration and ProductApproval remain authoritative. A receipt optionally resolves the exact active approval for the supplier/part/site/configuration at receipt; an unresolved receipt requires an explicit reason. Inspection completion is recording verification evidence, not authorization to release material. Historical imports create no approvals and never infer a supplier from part alone.

## Security and accounts

PermissionsGuard denies endpoints without a public policy, permission metadata, or explicit service-authorization exception. Generic files, collaboration and auth controllers declare the latter because their services perform record/session checks. Every new operational controller uses explicit permissions and internal audience defaults. New EntityAccessService resolvers mark inspections, plans, tests and repairs internal-only. Files require the uploader's private-upload authority or an authorized document/record relationship; document read no longer grants access to every internal file. File association and controlled-state checks run under aggregate locks.

Local bcrypt `$2a/$2b/$2y` credentials are verified only at bounded legacy cost; a successful login atomically rehashes to Argon2id if the hash/account state is unchanged. Passwords longer than bcrypt's 72 UTF-8-byte boundary cannot use legacy verification to avoid silent truncation; use the controlled reset path. Wrong passwords, disabled users, duplicate identities and unknown hash formats never produce a guessed conversion. Sessions/tokens are not migrated. Administrators can provision a local user and assign reviewed roles without sending mail.

Inspector can execute/complete inspections and create NCRs. Quality Manager can reopen, disposition and manage plans but has no user administration. Test Lab can synchronize reports, record repairs and create/review draft bench inspections. Engineering controls physical-feature/revision mappings. New grants are reference-seeded for new roles; existing customized roles are not silently overwritten. Review their grants explicitly before acceptance.

## Immutable evidence and concurrency

Released plan definitions, hashes and release provenance are protected by database triggers. New inspection snapshots freeze the released plan, part-specific specifications and known configuration/approval. Measurements preserve specification, units, limits, method and feature identity. Editing a reopened inspection supersedes measurements rather than deleting them, so NCR source links remain valid. Optimistic versions and MySQL row locks prevent lost updates. Reopening requires a dedicated permission, reason, activity entry and audit snapshot of the previous completion. Operational hard-delete endpoints do not exist.

Item disposition uses the source rule: every item needs PASS/FAIL/ACCEPTED; worst case determines the inspection disposition. Failed/accepted item dispositions need notes and scanned item evidence. Failed/accepted checklist rows need their own notes and row-associated scanned image. Receiving is shared once; delivery photos cannot satisfy an unrelated item's failure evidence. Numeric limits determine structured outcomes; a failed item measurement cannot be declared PASS. Bench DNF is retained separately from demonstrated failure.

NCR narrative sections removed from a draft are archived, preserving their identity and historical photo links. Caption/context changes have optimistic versions and before/after audit. Completed NCR evidence cannot be rewritten through generic file routes. Unknown legacy approvals, dispositions, owners and timestamps are retained/labeled, not invented as native approval history.

## Connected quality and recurrence

NCRs have relational incoming, FAI, qualification and validation origins. Database checks and service ownership checks bind origin kind to the correct record. Internal/unattributed NCRs can have no supplier. Defect lines preserve actual condition/specification/quantity and a controlled code. Manual NCRs begin with an unclassified OTHER line; detailed classification is an authorized annotation. Closed legacy NCR classification requires Quality disposition authority and a reason, without rewriting the historical disposition.

Physical feature UUIDs and part-scoped keys identify a feature. Balloon numbers are aliases. An FAI characteristic can be explicitly mapped to a feature and configuration revision; a mapped characteristic cannot be silently reassigned to an unrelated feature. Cross-revision comparisons require reviewed compatible mappings; incompatible mappings exclude the comparison and uncertain mappings remain candidates requiring engineering review. Confirmation re-evaluates current mappings.

The initial matcher requires the same supplier, internal part, stable feature, controlled defect code and deviation direction, with compatible/unknown site context. It includes CLOSED NCRs, ignores current product-approval status, and uses the administrator setting `qms.recurrence.lookbackDays` (default 1,825). Unknown suppliers/features are not guessed. A historical SCAR is displayed as a potential effectiveness concern, not proof of causality. The signal queue distinguishes candidates, confirmations and reasoned dismissals.

Creating an origin NCR, its defect lines, recurrence reviews, audit, notifications and outbox events is one transaction. A durable QualityCommand key binds actor/source/payload to the resulting NCR. Failed transactions leave none of the partial aggregate; replay after a committed but lost response returns the same NCR. Notifications and PENDING email deliveries commit before enqueue; worker sweeps recover enqueue failure. Only human-authorized actions can disposition, hold/release, issue/close SCARs, change approvals, grant concessions or require requalification. Existing FAI/SCAR four-eyes controls remain; FAI results cannot be added after review, and out-of-spec/failed characteristics cannot support FAI acceptance.

## Injector reporting and integrations

Recorded sync and configured reporting transport use the source green-band calculations, step labels, error/DNF rules, report-slot uniqueness, exclusions and ambiguity-safe serial resolver. A refresh upserts source reports without deleting permanent repair evidence or propagating bench deletions. Report selection order is preserved. Bench-to-inspection conversion is atomic and keyed by source selection/plan; it produces a provenance-marked draft under a released Fuel Injector plan and does not invent receiving/supplier approval evidence.

Repair attempts retain before/after snapshots and original identity. Retests must follow the before-test and repair date, match the same physical injector and belong to an open case. Held/scrapped cases cannot accept a retest. Deltas require matching measurement identity, units and specification bands; incompatibility produces an explanation, not a false effectiveness percentage. Passing repair history is permanent. Quick Entry records the source's six before/after measurement pairs and can atomically link the previous unsuccessful retest before the next attempt.

CarbonZapp defaults to disabled. `recorded` is local import only. `test-safe` requires a separately configured non-operational reporting URL; redirects are rejected and no equipment-setting APIs exist. `live` requires production configuration and belongs to a separate release decision. Credentials stay in deployment secrets.

Daily passed-test exports use the shop day (America/Denver by default), explicit source PDI aliases and one row per passed test, including retests. A daily reservation and immutable outbox payload commit together. Default mode is disabled; test-sink logs delivery metadata only. The Google adapter requires a reviewed dedicated tab and a fourth `PDI Delivery ID` column: a retry reads delivery keys before appending, recovering append-before-ack failure. RAW input preserves identifiers and prevents formula execution. Previously sent external days and late-arriving records require reconciliation before enabling a destination. The worker uses a bounded compare-and-swap outbox lease; crashed workers become retryable without relying on memory.
